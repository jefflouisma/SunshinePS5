# SunshinePS5 v0.1.2

Bug-fix release. Same scope as [v0.1.0](v0.1.0.md) (PS5 firmware 13.60, official Moonlight,
SDR H.264, 48 kHz stereo Opus, one controller), now also at 720p and 30 fps.

## Added

- **720p and 30 fps.** The host offers 1920×1080 and 1280×720 at 60 or 30 fps (H.264 SDR). It
  used to offer only 1080p60, so Moonlight set to 720p failed to connect.
- **Clear errors for unsupported settings.** A resolution, frame rate or surround audio setting
  the host does not offer is refused when the stream starts, with a message Moonlight shows
  (for example *"This host streams 1080p or 720p at 60 or 30 FPS. Change the resolution or
  frame rate in Moonlight settings."*), instead of *"Failed to start RTSP handshake"* and a
  firewall hint.

## Fixed

- **Starting or closing a game no longer ends the stream.** When the console changes video
  mode, its encoder fails reads for a moment (`0x81950009`), and the host ended the session with
  an error ("Connection terminated", error -1, in Moonlight). The host now reopens the encoder
  and continues; on hardware, closing and relaunching a game during one session recovered in
  0.4–3.7 s each time.
- **The picture no longer freezes for good after a lost frame.** The console encoder (Avcap2)
  sends a key frame (IDR) only when its stream starts, and the host ignored Moonlight's requests
  for a new one. One frame lost to the network, or dropped by the client (for example while its
  window is being resized), left Moonlight waiting for an IDR until the session ended. The host
  now answers Moonlight's IDR requests and reference-frame invalidations by restarting the
  encoder stream (about 55–85 ms, at most once a second); the next frame is an IDR and the
  picture recovers.
- **Closing the send terminal no longer breaks streaming.** The host writes its log to the
  connection opened by `send-to-ps5.sh`. In v0.1.0 and v0.1.1, once that connection was closed
  (Ctrl+C, closing the terminal) or lost, a failed log write aborted the next session: Moonlight
  reported *"RTSP ANNOUNCE request failed"* for every stream until the payload was sent again.
  Logging is now best effort and never blocks or fails host work; a line that cannot be sent at
  once is dropped.
- **The host follows the console to a new address.** The host used to stay bound to the address
  it started with, so moving the console to another network or giving it a new IP left the host
  unreachable until the payload was sent again. Between sessions the host now checks every
  2 seconds that its address still exists, and if not, moves its ports, web page and pairing PIN
  link to the console's new private address. It keeps the same process, controller and pairings.
  A stream in progress is never moved, and a `--bind` address is left alone.
- **A busy network interface no longer ends the stream.** A UDP send that hits a full
  interface queue (`ENOBUFS`) or socket buffer is retried for up to 20 ms; if it still fails, that
  frame or audio packet is dropped and the session continues.
- **Network errors no longer print failures.** A failed `accept()` during a network change
  printed a source-assertion line on stderr for every failure. It is now an `accept_error` event,
  at most once every 5 seconds, and the listener keeps serving.

New log events: `address_changed` (`from`, `to`, `web`), `address_lost` (no private address yet,
or the rebind failed and will be retried), `accept_error` (`errno`), `keyframe_request`,
`keyframe_restart`, `keyframe_first`, `keyframe_missing`, `source_lost`, `source_recovered`,
`send_drop`, and `media_error` (`stage`, `reason`) for every media failure that ends a session;
`video_timing` gains `key_frames`; `ready` lists the offered `modes`.

CI-only fix: an input-probe driver test no longer fails when its 20 ms watchdog fires before the
fake transport is launched on a slow runner.

## Documentation

- The host does not announce itself on the network; the README now says to add the console in
  Moonlight by IP address instead of suggesting it may be discovered.

## Known limitations

Unchanged from [v0.1.1](v0.1.1.md). After the console's address changes, add the new address in
Moonlight; pairing is kept.
