# SunshinePS5 v0.1.1

Bug-fix release for the v0.1.0 MVP. Same scope: PS5 firmware 13.60, official Moonlight for
macOS 6.1.0, SDR 1920×1080 H.264 up to 60 fps, 48 kHz stereo Opus, one controller.

## Fixed

- **No more resident controller holders.** In v0.1.0 the host that first created the virtual
  controller stayed resident (about 16 MiB) after a newer build took over, because the console
  removes a virtual pad when the descriptor that registered it is closed. Sending a new build now
  passes the open `/dev/hid` descriptor and the pad handle to the new host over a local socket
  (`/system_tmp/sunshineps5-takeover.sock`), and the old host exits completely. The console
  keeps the same controller, so it sees no disconnect and no new controller.
- **Upgrading from v0.1.0 works.** A running v0.1.0 host is still taken over through its
  original loopback port; its existing holder keeps that controller until the console reboots.
- **A controller removed outside the host no longer breaks input.** If the handed-over or parked
  controller no longer exists, the host drops it and registers a new one instead of failing every
  later session.
- **No controller loss after a gamepad-less session.** A host that received the controller and
  then served a session without a gamepad (for example the official client with keyboard only)
  keeps the descriptor open.
- The previous host releases its state-directory lock before its takeover listener closes, so
  the new host cannot race it while opening storage.

CI-only fixes: `test_settings` no longer depends on `TMPDIR` being exported at configure time,
a recovery-probe test no longer fails on Linux's coarse file timestamps, and the vendored ENet
offset computation is exempt from UBSan's null check.

## Known limitations

Unchanged from [v0.1.0](v0.1.0.md), except that hosts no longer stay resident after a takeover.
If the console's *"Who's using this controller?"* prompt belongs to a controller that has been
removed, the console keeps the prompt on screen and refuses other controllers until it is
rebooted; answer the prompt before stopping the host.
